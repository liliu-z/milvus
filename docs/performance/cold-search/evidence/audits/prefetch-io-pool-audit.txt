v83 dedicated speculative IO executor audit, 2026-10-10.

Changed source: internal/core/src/storage/storage_c.cpp only relative to v80 native core. Removed rejected v81 ordering change. The same candidates are validated and reserved in manifest order. Two fixed Folly workers are constructed only after an opt-in call successfully reserves at least one file. The ordinary cache warmup pool and its consumers remain unchanged. This bounds speculative synchronous IO concurrency to two; it is an experimental small-segment standalone path, not a broad high-concurrency throughput claim.

Input/admission: Go collection_prefetch.go still gates default-off flag, internal collection, <=4 segments, <=4096 rows, V3 and no actual index files; passes system fields, PK and vector IDs from actual schema. Native group selection and complete recorded file keys unchanged. Per-file <=4MiB; process-wide <=16MiB and16entries in unchanged ScopedFilePrefetch registry. Empty reservation creates no executor.

Ownership/concurrency: scope owns shared_ptr files; each queued callable owns its file. Take removes registry entry, can claim a not-yet-running read on the foreground, and the State mutex prevents two executions. An already-running read is awaited. No executor worker waits on a task it submitted to its own IO pool; normal reader/cache workers are separate. Scope cleanup cancels each generation; queued work returns without reading and in-flight data is discarded. State byte/entry budget is retained until the last owner, including queued or in-flight worker, is released. Thread retention does not retain raw segment buffers across Release.

Failures: no new throw construction, wrapping or error classification. Reservation/filesystem/URI failures keep existing fallback. Executor allocation/submission exceptions remain caught by BeginAutoLoadFilePrefetch; scope RAII cancels any successfully queued entries. Speculative OpenInputFile/ReadAt failure, OOM, short read and cancellation still use the unchanged native best-effort State; ordinary loader reads again and reports its original error. Synchronous in-flight IO is not promised to abort immediately on cancellation. End-before-consumption can cause an extra ordinary GET; v81 has an observed example, explicitly reported in the rejected-experiment report.

Verification before formal benchmark: core rebuild succeeded; scoped-prefetch-check PASS for real Parquet decode, consume-once, fresh read after release, FS identity, bytes/entry caps, cancellation/generation safety, foreground ownership, typed failure/recovery/corruption propagation. Two Int64PrimaryKeyFill regression tests PASS. These state tests do not alone prove executor scheduling; actual retained worker identities, fresh Go/native loads, raw GET timestamps and exact results are separately checked in formal v83. No CPU-heavy build/test/hash ran during that cohort.

New worker names include numeric suffixes (autoload_io0/1); the first observation using exact name equality returned an invalid empty match and is retained as such.
