INT64 primary-key optimization, v78 candidate

Source of the cost: ChunkedSegmentSealedImpl::bulk_subscript_from_state called PinPkIndex before checking requested field identity. This can lazily construct the whole PK index for any output field. v77 optimized FillPrimaryKeys alone; real e2e metrics moved about0.13ms from prepare_export to fill_output_fields, proving the first attempt incomplete.

Current change: inside bulk_subscript_from_state, only INT64 PK requests consider PinPkIndex. With existing preferFieldDataWhenIndexHasRawData=true and a physical internal PK column, use that column. SegmentInternalInterface::FillPrimaryKeys uses the same preference and reads owned/pinned cells directly into PkType, avoiding temporary proto data. The flag remains defaultfalse. External collections retain old PK behavior; absent columns retain the PK-index fallback. Other scalar/vector index routing below the PK branch remains intact.

Inputs/ownership: PreReduce filters invalid result offsets before FillPrimaryKey (compact group-by results already have no padding). PK schema remains INT64/non-nullable; row offsets retain requested order and duplication. GetChunkedColumn returns a shared owner; ProxyChunkColumn::ForEachResolvedRow prepares its group, resolves logical offsets and pins requested cells until all callbacks complete. memcpy avoids alignment assumptions. SearchResult read leases and the existing segment shared mutex remain held as before. No raw column, index or result is retained beyond the existing segment lifetime; Release protocol untouched.

Failures: CheckCancellation remains before the fast-path branch and keeps SegcoreError(FollyCancel). BulkValueAt uses existing group/cache/read/decode code without new catches or error rewriting; failures propagate to the existing C boundary. Index-only paths retain PinPkIndex and its integrity checks. All other PinPkIndex sites (PK existence lookup, deletes, PK range and retrieve filtering) are unchanged and can still materialize the retained lazy index when needed. This does not change retry classification or promise immediate cancellation of synchronous IO.

Verification: Int64PrimaryKeyFill.ManifestColumnUnsortedRepeatedOffsetsAndCancellation uses actual V3 Parquet files spanning3writer batches, compares unsorted/repeated/empty outputs to deterministic source data and preference-OFF indexed output, checks actual PK-slot IsCached transitions, and verifies cancellation numeric code. Non-PK reads, direct PK fill and late PK output leave the slot uncached; disabling preference loads it. ExternalVirtualPrimaryKeyUsesFallback verifies exact virtual IDs under preferenceON.
