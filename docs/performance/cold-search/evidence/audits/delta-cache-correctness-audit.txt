v71 delta-path metadata cache audit
Scope: only segmentLoader.loadDeltalogs ordinary parent/child readManifestDeltas uses GetLoadDeltaLogPathsFromManifest; public GetDeltaLogPathsFromManifest, external real-PK GetDeltaLogsFromManifestWithExtfs, writer transactions and other consumers unchanged.
Input: original GetDeltaLogPathsFromManifest -> GetDeltaLogsFromManifestWithExtfs(empty context) -> explicit-version loon transaction -> C manifest delta entries. Original filtering of <=0-entry markers and external/path resolution is preserved by calling the unchanged reader on every miss/bypass. No new error construction/classification or string conversion. Reader errors are returned unchanged and never cached.
Identity: exact positive-version manifest string, sha256 of deterministic full StorageConfig. Missing/invalid/latest versions and nil config bypass. Underlying properties builder also reads writer-format setting, which is not used by this manifest read; no external-spec properties on this ordinary-reader path. All FFI storage/Talon/credential/endpoint properties are covered by StorageConfig.
Lifecycle: explicit committed manifest version is immutable (also already cached in native Manifest::Make). Writers CommitManifestUpdates/AddDeltaLogsToManifest return a new version. Delta lists can remain cached across Release because they are descriptions only; each load opens the listed files via unchanged NewDeltalogReader. Parent/child descriptors have their own manifest keys.
Ownership/bounds: slices cloned on insertion and hit, immutable entries after publication; lock held only for LRU/map operations, never reader IO. Separate delta128entries/1MiB accounted cap; stats128entries/16MiB unchanged. Shared generic LRU exercised with errors, storage identity changes, mutable caller outputs, byte/count eviction and concurrent race tests.
Failure evidence: actual missing manifest errors twice then successful creation is not poisoned; invalid/latest/nil config bypass retains context errors; disabled wrapper calls original reader. Actual Milvus packed Parquet deletion test verifies repeated parent/child application, new version adds a delete, old version independent, removing a delete file after metadata hit produces an error without applying a partial DeltaData, recreating file recovers. Existing V1, placeholder, child error and external real-PK tests pass with race.
Limits: this does not change cancellation of underlying synchronous FFI/reads and does not claim to repair existing FFI error categories. No raw delete/PK/vector data is cached by this change. The measured phase improvement is ~0.08-0.09ms in adjacent short cohorts; whole-request v71 means regressed because of other stages, all samples retained.
